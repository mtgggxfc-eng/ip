## 运行本地回归

```bash
python -m pip install -r requirements-dev.txt
python scripts/build.py
python scripts/check.py
```

需要 Python 3.10+、Bash、Node 20+。check.py 不使用 SSH，不修改云平台、防火墙或真实服务。

可选浏览器回归：安装 Python playwright 和 Chromium 后运行 `python tests/test_hub_browser.py`。它自动在临时目录渲染页面，使用模拟机器 API；验证删除确认、取消、单机隔离、失败重试与旧组保护，不连接真实后台，不删除真实云资源。不加入默认 check.py 的浏览器依赖。

## 实际核心兼容测试

```bash
python tests/integration_ws.py --sing-box /path/to/sing-box --xray /path/to/xray
```

测试在临时目录创建配置，启动独立进程，最后结束并清理；没有全局系统代理修改。curl 强制不受 NO_PROXY 绕过，否则 loopback HTTP 请求可能产生假阳性。家庭出口测试检查 SOCKS 服务实际收到连接，不能只看 HTTP 返回成功。

## 试用中仍需完成

1. cloudflared 在真实 VPS 的运行、隧道连接及每个节点子域名证书传播；本轮已测真实资源 API，但未启动测试隧道连接器。
2. CF 边缘至 VPS 的三条 WS 链路，从外部客户端实际握手和出口；本地 origin 测试不能替代该项。
3. Certbot DNS/私有挑战 hook 及自动续期；当前没有为用户域名申请新版证书。
4. NVIDIA Services API 的真实 TCP 映射及 MAC 唯一匹配；无 API 授权时不能读取平台随机映射，通用映射表是用户/平台工具提供数据，不等于脚本自行发现。
5. 新版在授权试验 VPS 的完整安装、重复执行、重启、部分失败、卸载；目前没有执行新版部署。
6. 从用户自己的网络，以实际 v2rayN 导入最终链接，测试证书、出口、持续连接与速度。
7. 至少两台机器真实管理隔离：改一台国家/端口/出口，另一台配置、服务、日志不变。
8. 长时间连接、住宅上游切换、云端中断恢复和自动续期；实际回滚切换演练尚未做。旧 Worker、绑定、域名与 D1 数据备份已保存私有工作区。

不会把上述未完成项目写成“节点一定高速稳定安全”。节点能否在用户网络使用，必须有该网络的实测证据。CF 和 VPNGate 的供应/可达性不由本项目控制。

## 曾发现并修复的具体问题

- 只按 sing-box 名称扫描 unit 会漏掉本项目自己的 three-nodes.service；已加入，并测试重复发现。
- 本地 curl 可能因 NO_PROXY 直接访问测试目标；已强制通过代理，并验证住宅 SOCKS 实际连接数。
- 汇总切换后失败响应可能被原页面渲染成旧配置；已清空旧数据、拒绝错误响应并禁用保存。
- 提取代理列表是普通链接，不能附加请求头；改为 GET 携带明确机器编号，写入仍要求请求头和操作标记。
- 一个已失陷的 VPS 可能向汇总页面返回恶意 HTML；在汇总端按字段校验、限制响应体、强制 API 类型，不信任子机 Content-Type。
- 复制整个旧制品目录可能包含私人二维码/链接；增加明确发布白名单并要求检查。
- 直接替换旧域名会阻断旧代理的 config/report；增加精确旧凭据兼容，并观察切换后心跳更新。
- 旧服务 POST 返回纯文本 OK，原汇总代理误按 JSON 解析；现在转换固定状态响应。
- CF 拦截 Python 默认 User-Agent；面板请求曾修复，但授权函数实际漏改，2026-10-19 才补齐并通过真实函数测试。不能仅根据此前变更说明判定授权已修复。
- 私人模式在原生节点及 IP 面板均正常时仍需创建授权域名面板，否则汇总允许域名校验会拒绝裸 IP；已修正并加入回归。

# 同时输出直连与 CF 两组节点

## 当前需求

用户最终选择同时输出两组，取消此前讨论中的直连/CF 模式选择。初始回车自动 / 2 手动参数菜单保留；两者都生成可以建立的两组，默认国家 JP。

| 分组 | 角色键 | 节点别名 | 实际协议 |
|---|---|---|---|
| A 直连 | tcp | TCP直连 | VLESS Reality TCP |
| A 直连 | udp | UDP直连 | Hysteria2 UDP |
| A 直连 | home | 中转家宽 | VLESS Reality，经本机住宅 SOCKS |
| B CF | tcp | TCP直连（CF） | VLESS WebSocket TLS |
| B CF | udp | TCP替代（CF，非UDP） | Trojan WebSocket TLS，仍为 TCP |
| B CF | home | 中转家宽（CF） | VLESS WebSocket TLS，经同一个住宅 SOCKS |

角色键 udp 是历史兼容键，不能据此判断 B 组为 UDP。两组共享本机核心和住宅出口，不引入另一台 VPS。CF 组与直连组不是两套独立住宅上游；住宅出口故障可能同时影响两组 home。

## 安装和输出

1. 建立或补齐原生 Reality/Hysteria2/住宅入口，保留已有身份与内部端口。
2. 有私人汇总授权或自有 CF 授权时建立 CF 入口；即使直连本机测试通过，也保留 CF 备用组。
3. 分别测试 A/B 各角色，不因一组通过而隐藏另一组；复用验证缓存避免重复网络测试。
4. 第一个装饰框中依次显示 A 组和 B 组，链接保持独立整行，可一起复制。第二个框为管理信息，第三个框为需要处理的项目，框后无追加文字。
5. 无 CF 授权、云 API 失败或本机协议组件不支持时，说明本组缺失原因，不能借维护者的权限或编造链接凑六条。

CF 入口创建后，即使连接尚未就绪也保留真实已分配的候选链接；是否通过检查由分组状态明确表示。A 组公网地址/映射未知时保留实际配置并要求替换外部地址/端口；只对 A 组作此提示，不要求修改 CF 的 443。

## UDP 的配置能力与平台能力

prepare() 分别记录 udp_listener_supported（本机是否能绑定 UDP）与 udp_available（平台 UDP 映射能力/声明）。映射机器也尝试补建真实 HY2 本机服务，这样在组件创建成功时可以得到完整的 A3+B3。

本机生成 UDP 配置不等于平台支持公网 UDP。未确认平台 UDP 时，A 组 HY2 仅为待映射候选，不能标成可用；其本机 UDP 防火墙规则仍尝试放行。NVIDIA Other 不能当作 UDP，不为它伪建 UDP Other 服务。用户提供明确的 udp 映射表后才能尝试对应公网地址，仍保留独立外部验证的限制。若内核/容器无法创建 UDP 监听，则不伪造 A 组 HY2。

## 管理面板与证书

私人汇总授权和节点直连组不冲突。默认创建独立 CF 管理面板 HTTPS 入口，同时保留原生直连节点；节点流量由用户选用的链接决定，不会因为接入汇总就强制走 CF。

私人双组安装不重复申请公网 IP 证书，优先使用管理域名的 CF 边缘证书；需要备用直连域名证书时再走 DNS 验证。不会为随机映射的公网 80 强行申请 IP 证书；普通无 CF 授权安装仍使用原 IP 证书流程。已有证书与定时器按原有归属规则保留。

隧道面板不通过 HTTPS/API 检测时，不再一律提示“随机 IP 证书无法申请”，而提示隧道/DNS/边缘证书传播/认证等入口问题并指向日志。已知真实外部地址及面板端口时，尝试备用 direct 域名和 DNS 证书；后台 /api/provision 的 resource_mode=direct 可只建立本机的 DNS，不依赖创建成功的隧道。缺映射时不会把出口 IP 当成可用管理入口。

原版汇总页面国家、住宅端口、切换出口等功能保持原有 API；两组住宅节点共用本机出口配置。这里没有增加两套相互独立的国家策略。

## 文件与兼容

- native-links.json：只保留原生入口，不用 CF 入口覆盖。
- node-groups.json：direct/cf 两个字典，各含 tcp/udp/home 的已生成 URI，600。
- network-report.json：node_groups[group].generated_roles、ready_roles、checks；无完整节点 URI。仍区分配置生成、本机测试与外部入站确认。
- /root/three-nodes-links.txt：按 A 的 tcp/udp/home、B 的 tcp/udp/home 写入，最多六行纯链接，600。名称沿用兼容路径。
- /root/three-nodes-info.txt：三个结果框，第一框两个分组。
- links.json 与原 /api/links：保留每角色一个本机自测通过的优选入口，兼容旧面板消费者；不把它当作完整六条或外部验证清单。
- updater 未收到环境链接时先读 native-links.json，避免把六条文本中的 CF 链接误认成原生入口。
- 卸载只在确认 stack 归属时清理六行复制文件；其他目录规则不变。

## 验证与限制

本地回归覆盖直连和 CF 同时保留、原生地址不被 CF 覆盖、映射未知仍输出候选并标 UDP 未确认、单组握手失败仍输出真实已生成链接、六行复制文件及卸载。sing-box 与 Xray 各三次 loopback WebSocket 握手与住宅 SOCKS 路由测试通过。

Worker 的 DNS-only 分支测试了授权前校验、令牌隔离、只创建自有 DNS、不创建隧道、重试幂等与清理；原完整隧道分支保持兼容。公共工具没有独立外部入站检测服务，不能因本机自测通过就隐藏直连端口提醒。未将本地测试描述为所有 VPS 新装或用户网络六条全部可用的验收。

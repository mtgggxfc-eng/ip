# 私人汇总面板与安全

## 状态与目标

2026-10-18 试用版已部署。统一入口保留原页面布局，增加机器选择器和“新增机器”：选择哪台新机器，读取和写入哪台。每台新机器保留独立面板和节点服务。

已有旧 Worker 使用 global_config 全局表。不能直接把所有新机器都接入旧 /api/config，否则可能联动修改多台。新版通过各台独立面板的 API 管理，不把它们改为共享一份全局策略。

可选 LEGACY 服务绑定保留旧 Worker，显示为“原有住宅面板（旧机器）”分组。旧组里的机器在逐台迁移前仍遵循旧逻辑，不能假装它们已经按机器隔离。迁移需逐台确认原服务，不自动改旧 VPS。

## 为什么仓库使用者不能进入私人后台

公开的是程序，不是权限。仓库不含私人汇总地址的默认接入、管理员密码、CF API Token、登记码或机器令牌。

| 凭据 | 保存位置 | 能做什么 | 不能做什么 |
|---|---|---|---|
| ADMIN_USER / ADMIN_PASSWORD | Worker Secrets | 管理后台、机器列表、签发登记码、撤销机器 | 不出现在前端源码或 VPS 配置 |
| 一次性接入码 | 管理员签发后私下交给新 VPS；DB 只存 SHA256 | 15 分钟内登记管理员预定的一个机器编号 | 登录后台、读取列表、登记第二台、重复使用 |
| machine_token | 对应 VPS 的 hub.json；DB 只存 SHA256 | 更新、注销自身登记，管理本机分配的隧道/证书验证 | 改名称、管理其他机器、读取后台列表 |
| 独立面板账号密码 | 各 VPS；汇总 D1 中加密保存 | Worker 访问指定机器面板 | 代替汇总管理员登录 |
| CREDENTIAL_KEY | Worker Secret，32 字节随机密钥的 Base64 | AES-256-GCM 加解密面板凭据 | 不能公开，不能丢失后直接恢复解密 |

普通人运行项目默认部署自己的服务，register_hub() 在没有 URL 时不发任何接入请求。知道私人域名也仍需身份认证。一次性接入码用原子 UPDATE ... RETURNING 消耗，防并发重复登记。

面板凭据 AES-GCM 使用随机 IV，并将机器编号作为附加认证数据，防止把某一行密文移到另一台机器。机器令牌不能通过后台登录校验。HTML/机器列表不返回独立面板密码、管理密码、加密密钥或 API Token。

这不等于绝对安全：管理员凭据、机器自身 root、CF 账号或部署密钥被盗仍需撤销与轮换。正式上线宜另外使用 Cloudflare Access 限定管理员身份并启用账号多因素认证；不能仅凭一个可伪造的身份请求头放行。

## 请求隔离

- 后台需要服务端 Basic 身份认证，通过 HTTPS 使用；缺部署 Secret 时返回 503，拒绝访问。
- 管理请求必须有明确 X-IP-Machine，不以浏览器可控 URL 作为任意转发目标。
- 只代理固定 API 白名单。写入仅 /api/config 和 /api/switch，且必须有 X-Panel-Action: 1。
- 来源只能是 ALLOWED_PANEL_ZONES 中域名下的 HTTPS 面板；禁止 URL 内嵌账号、查询、碎片和任意路径。
- 解密对应机器凭据后向后端添加 Authorization，覆盖浏览器的后台授权，不转发其他机器凭据。
- 不跟随后端重定向，不把后端认证挑战、Cookie 或 Location 发给浏览器。
- 切换机器时取消上一台的未完成 GET；保存期间禁用选择器，防止把操作归到新选择的机器。
- /api/report 不对汇总前端转发。各机代理继续向本机报告，防后台数据串台。
- 兼容旧代理时，仅旧凭据、无 X-IP-Machine 的 GET /api/config 和 POST /api/report 转到 LEGACY 服务。不会开放旧安装脚本下载或旧凭据管理写入。原有机器在兼容分组中仍使用旧的全局配置。
- 旧 Worker 保存配置返回纯文本 OK；汇总代理转换成固定 JSON 状态，避免实际保存成功却被误报失败。

## D1 表

schema.sql 只创建 ip_machines、ip_enrollments，不修改旧 servers/global_config。机器表有 id、label、panel_origin、加密 credentials、令牌摘要、更新时间。接入码表有摘要、预分配机器编号、名称、到期时间、是否使用。

不保存机器完整实时日志。机器表另有 resources 账本，记录本机 CF 隧道、DNS 和 ACME TXT 的编号及内容。管理员删除时先撤销机器 API 令牌，再核对并清理本机资源；云 API 故障时保留账本让管理员重试，不恢复已撤销令牌。不会卸载节点或删除 VPS，但撤销隧道会停止依赖它的入口。其他机器不受清理影响。过期登记码定期清理，已消费的码不放回。

## 部署步骤

1. 备份现有 Worker 源码、绑定、路由和 D1 数据；不要把带密钥的导出放入仓库。
2. 构建。复制 wrangler.example.toml 为私有配置，填写新 Worker、新 D1、允许的面板区域。先用试验域名，不改旧域名。
3. 设置 ADMIN_USER、足够长的随机 ADMIN_PASSWORD、CREDENTIAL_KEY 为 Worker Secrets。私人代建另需 CF_API_TOKEN、CF_ACCOUNT_ID、CF_ZONE_ID、CF_ZONE_NAME；后者须属于 ALLOWED_PANEL_ZONES。CF 令牌限定对应区域 DNS 编辑、区域读取及指定账号隧道编辑，不能使用不必要的全账号权限。示例没有默认密码。
4. 在选定 D1 执行 schema.sql。若要兼容旧 Worker，添加 LEGACY 服务绑定，以及 LEGACY_USER/LEGACY_PASSWORD Secrets。
5. 测未登录拒绝、机器登记、选择/保存、国家/端口/日志隔离、失败提示、撤销；确认浏览器无子机密码。
6. 正式入口切换后保留旧 Worker，便于回滚。当前为用户授权试用；完整 VPS 安装、两台新机器的实际隔离和用户网络节点测试尚未完成，不能宣称稳定版验收通过。

### 新机器如何加入

管理员向 POST /api/enrollments 发送 {"label":"机器名称"}，使用后台 Basic 授权和 X-Panel-Action: 1；得到一个有效 15 分钟、只能使用一次的 code。

在新 VPS 的私有执行环境设置 IP_HUB_URL 与 IP_HUB_ENROLLMENT，再运行安装器。私人模式先用接入码调用 /api/provision，后台代建该机资源；独立面板通过后刷新登记。VPS 只保存自己的 machine_token 和隧道运行令牌。不要把 code 写进 README 或公共一键命令。

已认证的后台点击“新增机器”，输入名称后直接生成完整私人安装命令；使用浏览器原生对话框输入名称。命令只含本机单次接入码，不含管理密码或 CF Token；15 分钟内在自己的 VPS 执行，按回车自动安装。页面不会给公共访问者生成命令。“自动安装”不绕过首次私人授权。

## 汇总 API

| 接口 | 认证 | 功能 |
|---|---|---|
| POST /api/enrollments | 管理员 + 操作标记 | 签发一次性登记码，管理员决定名称 |
| POST /api/provision | Bearer 单次码或自身机器令牌 | 私人资源代建/恢复，只返回本机运行凭据 |
| POST /api/dns-challenge | Bearer 机器令牌 | 仅允许本机 direct 子域名的 ACME TXT |
| POST /api/register | Bearer 一次性登记码 | 登记指定机器，返回机器令牌 |
| POST /api/machine | Bearer 机器令牌 | 只更新自身面板地址和凭据 |
| DELETE /api/machine | Bearer 机器令牌 | 只注销自身 |
| GET /api/machines | 管理员 | 不含密码的机器列表 |
| DELETE /api/machines/:id | 管理员 + 操作标记 | 撤销对应机器及其令牌 |
| GET / | 管理员 | 原布局 + 机器选择器、私人命令生成 |
| 白名单 /api/* | 管理员 + 机器编号 | 只代理对应机器的管理请求 |

## 轮换、备份与回滚

- 泄露登记码：等到期或删除该摘要。已消费的码不能再次使用。
- 泄露机器令牌：管理员删除该机器，重新签发登记码并在 VPS 删除旧 hub.json 后登记；不影响其他机器。
- 泄露管理员密码：更新 Worker Secret；同时检查登记记录和机器清单。
- 更换独立面板密码：先改本机 auth.json，再使用该机令牌刷新登记；不要重置其他机器。
- 轮换加密密钥：先备份 D1 和旧密钥，使用旧密钥逐条解密、用新密钥重加密并保留机器 ID 附加认证数据，再切换 Secret。直接覆盖 Secret 会使全部旧凭据无法解密。迁移工具目前尚未实现。
- 回滚：恢复旧路由到保留的旧 Worker。新建机器仍有独立面板，节点继续运行；不要删 D1 或 Secret 来“回滚”。

## 私人资源与公共项目隔离

公开代码不等于公开使用资源。陌生人没有管理员签发的码，无法从 /api/provision 创建域名或隧道；知道域名和源码仍需身份认证。默认公共安装没有私人地址、私人 API Token 或默认共享登记码。

私人部署由 Worker 保存 CF_API_TOKEN 并代建该机器唯一的隧道、四个专属子域名及可选直连备用记录。只返回 machine_token、单隧道运行令牌和对应域名。重复执行使用机器令牌恢复同一份资源；不会创建另一台机器，也不下发 CF 管理令牌。

DNS 证书备用使用 /api/dns-challenge。服务端从机器资源账本决定唯一允许的 _acme-challenge.direct-机器编号.域名；客户端不能自选目标域名，最多四个未清理验证。Certbot manual auth/cleanup hook 可自动调用，不需要把 CF API Token 放入 VPS。

CF 管理令牌仍是敏感权限，留在 Worker Secret 并不等于没有风险；应限定区域/账号，保护 Worker 编辑权限、CF 账号和 Secrets。机器令牌或隧道运行令牌被盗时，攻击者仍可能影响对应机器或消耗其流量；它不是硬件绑定。管理员应单独撤销该机资源。流量配额仍可能按 CF 账号共享，不能把独立隧道说成独立账号配额。

本地安全测试及真实试验域名覆盖：未知码拒绝、单次码不能再次登记、重试复用隧道、响应没有 CF API Token、本机 TXT 创建/清理、只清理测试机器资源。线上使用专门的账号级 API Token，仅对应区域 DNS 编辑/区域读取及账号 Tunnel 编辑；无 Worker 编辑权限。隧道编辑权限仍属于账号级，靠后台所有权账本约束每台机器。

旧 Worker、绑定、域名和原 D1 数据已在部署者的私有工作区备份，未进公共仓库。上线后已观察到原有代理心跳继续更新。真实浏览器已验证受信 HTTPS、原布局、旧分组读取及私人命令生成；没有为验收改动旧组国家、端口或节点。
